# Ghost Atlas Chat-Derived Execution Doctrine — 2026-09-11

## Status

This artifact reverse-engineers the recurring execution laws demonstrated across the governed estate work culminating in the ODIN/EDEN resident-forensics recovery. It does not create a new organ, control plane, runtime, or authority. It sharpens the existing Software Factory contract.

## Canonical law

`COMMAND -> DISCOVER -> CANONICALIZE -> PACKETIZE -> BUILD -> OBSERVED EXECUTION -> VERIFY -> SYNTHESIZE -> ACCEPT -> SECURITY REVIEW -> PROOF -> ARCHIVE -> PROMOTE`

No downstream PASS may substitute for a missing upstream observation.

## Reverse-engineered laws

1. **Convergence before invention.** Search the existing estate, identify canonical ownership, patch the owner, and create new architecture only when no existing organ can absorb the requirement.
2. **Repository truth before design.** Inspect current branches, manifests, Build Truth, runtime bindings, provider evidence, tests, and proof artifacts before changing implementation.
3. **One run, one lineage.** A software objective is represented as a correlated run with objective, source baseline, branch, packet lineage, artifacts, verification, deployment/runtime evidence, proof, blockers, and final state.
4. **Compute is not evidence storage.** GitHub may store source and receipts without being the execution substrate. Hosted CI is optional redundancy, not canonical execution truth.
5. **Runner neutrality.** EDEN, ODIN, Render, local execution, or another explicitly governed executor may satisfy execution only by returning admissible observed evidence.
6. **No false green.** Missing runner allocation, missing heartbeat, missing credentials, unavailable external dependency, absent proof URI, or digest mismatch produces BLOCKED/FAILED truth, never synthetic PASS.
7. **Physical boundaries stay physical.** A cloud control plane cannot claim a resident device executed work without a resident receipt or equivalent observed runtime evidence.
8. **Receipts are first-class.** Execution proof must identify executor, evidence class, outcome, exit code, artifact digest, proof URI, observation time, and useful telemetry. Generated artifacts are SHA-256-addressable where practical.
9. **Evidence must bind to the artifact.** A successful command with the wrong artifact digest does not verify the build under review.
10. **Verification is layered.** DevOS verifies engineering/runtime facts; PROMETHEUS synthesizes evidence and contradictions; SECA evaluates acceptance; Medusa evaluates release/security; ProofGrid publishes the evidence chain; Thoth archives lineage.
11. **Proof class substitution is forbidden.** Static checks cannot substitute for runtime observation; synthetic fixtures cannot substitute for estate census; mergeability cannot substitute for verification; a green website cannot substitute for machine wake.
12. **Bounded recovery is part of normal operation.** When a provider fails, route through an existing authorized substrate while preserving the same acceptance and proof gates.
13. **Push only governed outputs.** Resident tooling may commit/push only explicitly enumerated generated evidence paths; arbitrary repository mutation remains outside the execution contract.
14. **Credentials are capabilities, not artifacts.** Authentication may be consumed by a bounded executor but must never be printed, archived into proof, or treated as canonical state.
15. **Scaffolding is not completion.** Branches, wrappers, manifests, prompts, and PRs are IMPLEMENTATION until the demanded runtime/proof gate executes.
16. **External blockers remain explicit.** The final state distinguishes VERIFIED COMPLETE, IMPLEMENTATION COMPLETE — EXTERNAL BLOCKER, and PARTIAL; it does not bury blockers inside prose.
17. **Every blocker should yield a reusable repair.** The GitHub Actions runner outage produced resident execution; the repair pattern must become reusable estate behavior rather than a one-off workaround.
18. **Sprint handoff requires executable truth.** The next sprint starts from the latest proven state and inherits unresolved blockers as named inputs, not hidden assumptions.

## Execution evidence classes

- `resident-observed`: a physical/local resident body such as EDEN or ODIN executed the artifact and emitted proof.
- `runtime-observed`: a governed deployed runtime such as Render executed/observed the artifact and emitted proof.
- `external-observed`: an explicitly governed external executor emitted admissible evidence.
- `none`: no admissible execution evidence exists; execution must be BLOCKED.

## Failure-resolution ladder

1. Observe the failure and preserve raw evidence.
2. Determine whether the failure is code, configuration, provider, credential, runner, physical-device, or proof-class related.
3. Do not mutate healthy code to compensate for an external execution failure.
4. Prefer an existing alternate execution substrate.
5. Preserve canonical ownership and the same acceptance gates.
6. Emit a receipt identifying the alternate executor and evidence class.
7. Sync governed evidence back into the canonical repository/PR.
8. Re-run downstream DevOS -> PROMETHEUS -> SECA -> Medusa -> ProofGrid -> Thoth gates.
9. Promote only after the new route is proven.
